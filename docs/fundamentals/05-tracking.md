# Staying locked

> **Who this is for:** You know acquisition hands over a rough code phase and Doppler for each satellite. You want to know how the receiver keeps hold of the signal from then on and turns it into precise timing.

> **You will learn:**
> - Why tracking is a pair of feedback loops, one for the code and one for the carrier, and what each loop is built from
> - How early, prompt and late correlators and a discriminator tell the code loop which way to move
> - How a Costas loop recovers the carrier phase and the data bits, and why an FLL pulls in first
> - What loop bandwidth trades off, and what losing lock and a cycle slip look like

This page is conceptual. The series continues with [reading the message](06-navigation-message.md).

## Two things to follow

Acquisition gives a code phase good to half a chip (150 m) and a frequency good to a few hundred Hz. Both drift continuously: the satellite moves, the receiver moves, the oscillator wanders. Tracking is the process of continuously re-estimating both and steering the receiver's replica to follow. It runs for as long as the satellite is in view, which can be hours, and every measurement in the rest of this series comes out of it.

The receiver does this with two coupled feedback loops, one for the code and one for the carrier. They have the structure of the phase-locked loop found in any radio, and the vocabulary is borrowed from there. Each loop is a cycle of four parts, repeated once per code period (1 ms for L1 C/A):

```text
 samples --> correlator --> discriminator --> loop filter --> NCO
                 ^                                             |
                 +------------- replica code or carrier -------+
```

**Numerically controlled oscillator (NCO).** The replica is generated by an NCO, a digital oscillator. It keeps a phase, adds a step proportional to the commanded frequency at every sample, and uses the phase to look up the replica: a sine and cosine for the carrier NCO, a chip index for the code NCO. Changing the step changes the frequency, and the phase stays continuous through the change.

**Correlator.** The incoming samples are multiplied by the replica and summed over the code period, the same cross-correlation acquisition uses, now at a single code phase and frequency. The sum is complex. Its real part is the in-phase component $I$ and its imaginary part the quadrature component $Q$. Summing over one period and starting afresh is sometimes called integrate and dump, and the 1 ms sum is a coherent integration.

**Discriminator.** A discriminator is a function of the correlator outputs whose value is an estimate of the replica's error: how far it is early or late, or how far its phase is off. It is the loop's sensor.

**Loop filter.** The discriminator's output is noisy from one period to the next. The loop filter smooths it and turns it into a frequency command for the NCO. How strongly it smooths is set by the loop bandwidth, the subject of a later section.

## The code loop

The code loop keeps the replica code aligned with the received code. It cannot tell from a single correlation whether the replica is early or late, because correlation power is symmetric around the peak. So it runs three correlators at once: the prompt replica, one shifted half a chip early, and one shifted half a chip late.

```text
 correlation
 magnitude        prompt
     ^              *
     |           *     *
     |        *           *
     |     *                 *
     |  *                       *
     +--+--------+--------+--------+--> replica offset
      early    prompt    late
             -1/2    0   +1/2 chip
```

If the replica is aligned, the early and late correlators are equal. If the replica is late, early is larger than late. The difference between them, normalized, is the error signal. With $E$ and $L$ the complex early and late correlator outputs, a common code discriminator is

$$
e_{\rm code} = \frac{\lvert E \rvert - \lvert L \rvert}{\lvert E \rvert + \lvert L \rvert} .
$$

It is zero when the replica is aligned, positive when the replica is late, and its size grows with the misalignment while both taps sit on the correlation peak. Dividing by the sum makes it independent of the signal strength. Because it uses magnitudes, it works before the carrier phase is known; summing magnitudes over several periods before forming it is non-coherent integration, and it averages noise down without needing the carrier phase to stay put.

The loop filter turns $e_{\rm code}$ into a small correction to the replica's code rate. This is the delay-locked loop, the DLL, and the prompt correlator's alignment is the receiver's measurement of when the code arrived, which becomes the pseudorange. A well-designed DLL in the open sky tracks the code to about one hundredth of a chip, a few meters of raw precision before any averaging: a chip is 293 m, so a hundredth is about 3 m.

The DLL does not have to follow the satellite's motion on its own. The Doppler that compresses the carrier compresses the code by the same fraction, so the carrier loop can tell the code NCO how fast to run. This is carrier aiding. A Doppler of 1 kHz on L1 is a fraction $1000/1.57542\times10^9$, 0.63 parts per million, which moves the code by about 0.65 chip per second. With aiding, the DLL only corrects what is left and can be made very slow.

Moving the early and late taps closer to prompt sharpens the tracking and reduces the effect of multipath, if the front-end bandwidth is wide enough to preserve the sharp peak. This is one reason survey receivers want wide front-ends.

## The carrier loop

The carrier loop keeps the replica carrier in phase with the received one. Its discriminator is the phase angle of the prompt correlator output. If the replica is exactly on frequency and phase, the correlation lands entirely on the $I$ axis, and any $Q$ component means a phase error. The loop filter adjusts the replica frequency to drive $Q$ back to zero. This is a phase-locked loop, a PLL.

The data bits complicate it. Every 20 ms the data message may flip the sign of the signal, which looks like a sudden 180 degree phase jump. A plain PLL would try to chase it. The Costas loop, the standard answer, uses a discriminator that is insensitive to sign. With $I$ and $Q$ the prompt correlator output, the phase error in cycles is

$$
e_{\rm phase} = \frac{1}{2\pi} \arctan\frac{Q}{I} .
$$

A data bit that flips the sign negates both $I$ and $Q$ and leaves their ratio unchanged, so a flip is ignored. The discriminator reads correctly for errors up to a quarter cycle either way. Once the loop is locked, the sign of $I$ is the data bit, up to an overall sign that the message decoder resolves from the preamble, so tracking and demodulation come out of the same loop. On pilot signals, after removing any secondary code, a plain PLL with its stronger error signal can be used instead.

When the carrier loop is locked, two things are true. The $I$ correlator output is a clean stream of data bits, which the next page decodes. And the accumulated phase of the replica carrier, the total phase its NCO has run through, is a measurement of how the distance to the satellite has changed, cycle by cycle, with a precision of a millimeter or two. That is the carrier-phase observable, and it is the basis of RTK.

Before the PLL can lock, the frequency has to be within a few tens of Hz, which acquisition does not guarantee. Receivers therefore pull in with a frequency-locked loop, an FLL, first. Its discriminator measures how much the prompt phase turned between two successive correlations, $\Delta\theta$ in cycles, and a steady turn means a frequency error

$$
\Delta f = \frac{\Delta\theta}{T_{\rm int}} ,
$$

with $T_{\rm int}$ the time between correlations. A turn of 0.05 cycle per 1 ms period, for example, is a 50 Hz error. The FLL only needs to be in the right neighborhood. An arctangent of the turn reads it unambiguously up to a quarter cycle per period (a data-bit flip between the two correlations looks like a half-cycle turn, so the discriminator folds at a quarter), which is ±250 Hz for $T_{\rm int}$ = 1 ms. That is enough to cover the 250 Hz a 500 Hz acquisition bin can leave, and interpolating between bins usually leaves much less. Once the frequency error is small, the receiver switches to the PLL.

## Loop bandwidth

Each loop's filter has a bandwidth, the loop bandwidth, which sets how quickly it responds. A loop with a bandwidth of a few hertz settles in a few tenths of a second. A wide bandwidth follows fast changes, which a moving receiver or a poor oscillator needs, but lets more noise through into the estimate. A narrow bandwidth averages more noise away but loses lock if the signal moves faster than it can follow.

The noise side of that trade has a simple form for a strong signal. With $B$ the loop's noise bandwidth in Hz and $C/N_0$ the carrier-to-noise density ratio as a plain number (not in dB), the thermal-noise phase jitter of a PLL is about

$$
\sigma_\phi \approx \frac{1}{2\pi}\sqrt{\frac{B}{C/N_0}} \quad \text{cycles}.
$$

At 45 dB-Hz, $C/N_0 \approx 31600$ Hz, and with $B$ = 5 Hz that gives 0.002 cycle, under half a millimeter on L1. That is the thermal-noise floor; the measured carrier phase is good to a millimeter or two. Quadrupling the bandwidth doubles the jitter; losing 6 dB of signal does the same. Real receivers do worse than this because the oscillator and multipath add their own errors.

The filter itself is usually of second order: the frequency command is a constant times the latest error plus another constant times the running sum of past errors, so a steady frequency offset is driven to zero phase error. Typical values are 1 Hz or less for the code loop, which can afford to be slow because the carrier loop can aid it, and 10 to 20 Hz for the carrier loop on a moving receiver. Choosing these is the main tuning decision in a receiver, and the right choice depends on the oscillator from the previous page.

## Losing lock

Under a bridge the signal disappears, the correlator outputs become pure noise, and the loops wander. The receiver watches two lock detectors: the prompt correlator power against the noise estimate (its C/N0 estimate), and a phase lock indicator that compares the $I$ and $Q$ powers and is near one when the energy sits on the $I$ axis. When they fall below thresholds for long enough, the channel declares loss of lock and goes back to acquisition, now with a narrow search around its last known state.

The quiet version of this problem is the cycle slip. If the signal fades briefly or the receiver jerks, the carrier loop can relock one or more cycles away, or half a cycle away in a Costas loop, with the code loop barely noticing. Subsequent accumulated carrier-phase measurements retain that jump until it is corrected: one wavelength per whole cycle, or half a wavelength for a half-cycle slip. For a meter-level fix it does not matter. For RTK it is the main enemy, and every RTK engine spends effort detecting slips so that it can restart the integer estimate for that satellite.
